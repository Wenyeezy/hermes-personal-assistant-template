# Project roadmap

Reviewed: 2026-09-21. This roadmap records direction, not release-date promises.

## Available in this documentation update

- [x] A [project map](docs/project-map.md) connecting Hermes, HIIS and Digital Assets Lab.
- [x] An explicit distinction between public scaffolding and private development.
- [x] A [fictional crypto/RWA evidence walkthrough](examples/digital-assets-evidence-demo.md).
- [x] [Community entry points](COMMUNITY.md) and structured onboarding/bug feedback templates.

The existing Easy Setup scaffold and its tests remain the runnable public
entry point. The walkthrough is a reading exercise, not a plugin release.

## Next: make one experience reproducible

- [ ] Observe a small first cohort using the scaffold; capture the first
  confusing step, expected behavior and outcome. Three to five participants
  is an initial recruitment goal, not an existing user count.
- [ ] Fix and document one reproducible onboarding failure.
- [ ] Package a standalone fictional-data HIIS/Lab replay with expected
  outputs, explicit unknown states and a correction path.
- [ ] Have someone other than the maintainer reproduce that replay from the
  documented public inputs.
- [ ] Publish a dated update linking the exact change, verification and
  remaining limitation.

## Later, after those results

- [ ] Decide licensing and contribution terms before presenting a broadly
  reusable plugin distribution.
- [ ] Define the smallest separately installable HIIS package.
- [ ] Verify one explicitly scoped live source path and document freshness,
  coverage, rights and cost limitations before announcing live support.

Use [Discussions](https://github.com/Wenyeezy/hermes-personal-assistant-template/discussions)
for priorities and research questions, and [Issues](https://github.com/Wenyeezy/hermes-personal-assistant-template/issues)
for concrete reproducible work. No user numbers, cost savings or performance
metrics are inferred from repository activity.
